## Limits and release implications

- All seven requested areas were inspected. General JSON bodies have route size bounds and Node HTTP deadlines; there is no separate per-account concurrent-body count. Raw socket/file-descriptor exhaustion was not attempted, so this is a note, not an additional finding.
- Import decompression is bounded in bytes and depth; worst-case object-graph amplification at the 256 MiB maximum was not load-tested. No private inputs were opened or copied.
- Source creates HTTP servers without custom body deadlines (`app/server.mjs:480`); Node 24 defaults provide a 300-second request deadline with periodic timeout checking, rather than an application upload-idle deadline. The reproductions use the real public ingress handler locally; deployed reverse-proxy deadlines may shorten the window and need operator review.
- The confirmed deletion issue blocks context acquisition for gameplay; it does not demonstrate a process crash or data disclosure. Public sign-up should remain off until these findings are addressed and owner approval is obtained.

## MP14 fixes and validation

START `d51c63d33e3cfaee827222fda555f04a782c1007`, Node 24.21.0. Both findings
above are **Fixed in MP14**; their original evidence and historical recommendation
are retained. Public sign-up remains off pending owner approval.

MP12C2-2: the durable picker fence destroys that picker's unfinished body
requests. Deletion reserves its closing entry briefly under the residency queue,
then waits for revocation and close outside it. Closing entries are excluded
from idle/capacity eviction. The activated audit regression requires deletion to
finish and the upload to be cancelled without a client abort. A separate routing
regression holds an accepted write through the fence and checks that unrelated
reads and a capacity acquisition still finish during its drain. The existing
MP5 deletion and crash files are unchanged.

MP12C2-1: owned backup bodies arrive under the existing MP7 byte reservations
before global parser admission. Wire sizes and gzip/JSON/depth limits remain
enforced. `multiPicker.importBodyIdleMs` defaults to 30,000 ms; no bytes during
that interval returns 408, closes the connection and releases admission. Tests
use 200 ms, cover renewal on bytes and a zero-byte chunked body, and verify
recovery without mutation. Two unfinished owners leave a third complete upload
able to reach validation. An active completed restore still occupies the global
parser/apply slot and refuses another complete upload with 503 and Retry-After 5.
The legacy streaming reader and option-absent routing remain unchanged.
