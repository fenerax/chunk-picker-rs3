## Findings, ranked by severity

### R1 — High: authenticated stream exhaustion and slow-reader buffering — fixed

**Routes/location:** `GET /api/events`, `GET /overlay/events`; START `app/server.mjs:1617`, `:1105`, `:1139`; candidate `app/server.mjs:699`, `:1635`, `app/overlays.mjs:270`, `app/security/request.mjs:110`, `:135`.

**Attack:** A member, viewer or holder of one scoped overlay key opens thousands of SSE connections. Each retains a socket and heartbeat. Several picker broadcasts ignore `write()` returning false, so an authenticated client that stops reading can accumulate buffered revisions/worker events. Overlay broadcasts notice backpressure but previously called `end()`, which can still wait for a stalled socket to drain. No administrator capability is needed.

**Fix:** Shared process-wide maximum of 64 open picker/overlay streams, at most 16 per invite or overlay credential (the cloud review proposed eight; raised at integration because the master link covers every tab and device); all master sessions share one identity. Reservations happen synchronously before response headers and are released once on finish/close. Excess streams receive 429 with Retry-After. Picker broadcasts and heartbeats destroy slow consumers; overlay backpressure also destroys the socket. Ordinary revoke/close remains graceful. HEAD does not reserve a stream.

**Evidence:** HTTP tests exercise the same invite through two sessions, overlay and picker global exhaustion, and admission after disconnect. Unit tests exercise idempotent release and destruction on backpressure. The synthetic probe, run with the proposed cap of eight, opens 12 streams: START accepts 12; candidate accepts eight and refuses four. This is a connection-budget test, not an internet-scale load test.

### R2 — Medium: ordinary JSON allowed excessive size and nesting — fixed

**Routes/location:** POST `/api/command`, `/api/profile/preview`, `/api/action-session`, `/api/feedback`, overlay management and other ordinary JSON handlers; START `app/server.mjs:103`, `:254`; candidate `app/server.mjs:105`, `:256`, `app/security/json.mjs:3`, `app/overlays.mjs:56`.

**Attack:** A member sends concurrent near-32 MiB ordinary command objects or deeply nested arrays/objects. Buffering, decoding and JSON.parse allocate on the HTTP process. Feedback additionally recursively redacts the parsed object; thousands of levels produce a stack overflow. Byte limits alone do not bound object depth. Throwing from the original request async iterator while consuming an oversized chunked body could also destroy the socket before the 413 reply.

**Fix:** Ordinary bodies now default to 1 MiB. Existing smaller limits remain: 8 KiB for invitation/plugin/sync/intent handlers, 16 KiB for feedback, 64 KiB for sandbox. A quote/escape-aware scan rejects nesting beyond 128 containers before parsing; JSON.parse still validates syntax. Overlay management uses the same depth check with its existing 8 KiB byte cap. Body iteration preserves the socket for an error reply, then closes incomplete rejected uploads. Backup/import routes retain their separate streaming parser, depth limit 128, compressed upload cap and 256 MiB decompressed limit.

**Evidence:** HTTP tests send deeply nested commands/overlay bodies, declared oversized JSON and oversized chunked JSON; expect 400/413, no saved revision, and an available session endpoint afterwards. Parser tests cover the exact depth boundary, 100,000 nested arrays, malformed JSON and escaped delimiters inside strings. The retained benchmark compares three 8 MiB invalid commands per fresh process: START parses then returns 400; candidate rejects with 413.

### R3 — Medium: sustained authenticated calculation spam — fixed within the calculation surface

**Routes/location:** GET/HEAD `/api/tasks`, `/api/helper-drops`, `/api/teleports`, `/api/training-plan`, `/api/area-check`, `/api/predict`, `/api/death-estimates`, `/api/chunk-planning`; POST `/api/sandbox/evaluate`, `/api/prediction-intent`, `/api/pool-ranking-intent`, `/api/profile/preview`, `/api/runemetrics/preview`, `/api/original-sync/preview`; `app/server.mjs:1219`, `app/security/request.mjs:90`.

**Attack:** A valid member repeatedly requests different chunks/plans, or repeatedly submits intent/preview requests. Worker queues have finite depth, deadlines and bounded caches, but sequential callers can continuously consume available CPU, and identical requests can accumulate response waiters. Existing anonymous limits do not apply to an authenticated member. GET/HEAD can perform calculation work even without a mutation body.

**Fix:** One fixed-window budget across these routes and methods: 600 requests per minute per stable invite identity, 1,200 per minute globally. The cloud review proposed 60 and 240; integration raised them because opening one chunk costs three or four budgeted requests and the master link shares one identity, so 60 could refuse ordinary map browsing. All sessions of an invitation share its budget regardless of client IP; the private master shares one budget. Reservations occur before calculation/body receipt, include invalid attempts, do not refund on failure, and return 429/Retry-After. Active buckets cannot be evicted to reset limits; global admission is checked before charging. Viewer `/api/tasks` reads already-saved bytes and is exempt. Existing worker isolation, queues and deadlines remain necessary. Limits are configurable through the existing createServer `rateLimits` option.

**Evidence:** Unit tests verify rollover, cross-identity global ceilings, capacity overflow and synchronous admission. HTTP tests exhaust a budget through different routes, sessions, IPs and methods, while allowing cheap reads and normal saves. Seventy sequential prediction requests in the probe yield zero request-budget refusals at START and ten at the candidate. The synthetic fixture has no calculator: this proves HTTP admission, not real planner throughput or fairness.

### R4 — Medium: plugin authentication failures bypassed anonymous limits — fixed

**Routes/location:** GET `/api/plugin/v1/status`, `/api/plugin/v1/tasks`, POST `/api/plugin/v1/report`, and requests presenting a `gpk_` credential to other routes; `app/server.mjs:612`, `app/game-plugin.mjs:311`.

**Attack:** Send an arbitrary or revoked plugin bearer to the exact plugin endpoints, or any picker route. The plugin dispatcher runs before the ordinary anonymous limiter and throws 401. Its four-per-second limiter runs only after successful key authentication. Repeated failures therefore evade the request budget and repeatedly scan up to 1,000 stored key records. Cookie fallback is correctly forbidden, but did not address request volume.

**Fix:** Charge plugin authentication failures and rejected off-scope plugin credentials against the existing canonical client-address anonymous budget. Valid plugin traffic retains its dedicated four requests/second/key limit and native no-Origin exception. No cookie or invite can substitute for a plugin key.

**Evidence:** HTTP regression sends bad plugin credentials across exact plugin routes and ordinary routes: two configured attempts return 401, subsequent attempts return 429/Retry-After, and a different forwarded address retains its own allowance. Existing plugin scope, revocation and native-client tests pass.

### R5 — Medium: unknown API routes consumed bodies before refusing — fixed

**Routes/location:** unknown `/api/*`, e.g. POST `/api/not-a-route`; START `app/server.mjs:1196`, `:1638`; candidate `app/server.mjs:1203`, `:2152`.

**Attack:** A signed-in member sends an unfinished body to an unknown API route. The permission lookup returns undefined but does not reject it, so the handler waits for and parses a body before eventually returning 404. This retains request/activation resources on a route that cannot succeed. It also contradicts the declared default-deny contract; this was not an observed bypass of an existing admin handler.

**Fix:** Reject an undefined API permission before reading the body: 404 by default, preserving the existing explicit 405 responses for unsupported chunk-section/usage methods. Close incomplete rejected uploads after sending the reply. Delegated overlay/plugin endpoints retain their own explicit scopes and route rejection.

**Evidence:** An HTTP regression sends headers declaring an unfinished body, then sends no body. It must receive 404 and Connection: close without waiting for the upload. An enumeration of every declared private API route confirms anonymous requests receive 401; all administrator entries reject members before mutation (the disabled legacy import surface returns 404).

### R6 — Medium: whole-service admission remains incomplete — report only

**Routes/location:** POST `/api/command`, `/api/action-session`, `/api/member-restore[/preview]`, `/api/restore[/preview]`, `/api/import[/preview]`; GET `/api/backup`, `/api/backups/:id`, `/api/history`; `app/server.mjs:1650`, `:1978`, `:1623`, `app/backup-transfer.mjs:6`, `app/storage/store.mjs:1009`, `:1132`.

**Attack:** A malicious authorized member submits many valid saves/action sessions or repeatedly restores its own map, queues many retained-backup reads, or holds upload connections until Node's request timeout. Administrative restore/import is protected from members, and there is one active HTTP import gate, but that gate can be monopolized by a slow upload. The 256 MiB import cap bounds each parsed document, not all sockets, buffered ordinary bodies, queued mutations or expensive downloads together. Per-IP anonymous limits do not defeat distributed anonymous traffic either.

**Proposed fix:** Add a unified active-request/body-byte admission controller, separate budgets for durable writes and backup/download work, short upload progress/total deadlines, bounded mutation/read waiters and deployment-level connection controls. Preserve action-receipt retry semantics and allow normal large backups. This crosses storage queues, import UI, worker scheduling and proxy settings, so it needs a designed follow-up rather than an arbitrary low global POST cap. Rate-limited requests still incur credential verification before their rejection; these application budgets are not an edge flood defense. Calculation and SSE fixes above reduce specific attacks but do not solve this finding. Not load-tested to exhaustion.

### R7 — Medium: leaked reusable invite grants renewable access until manual revocation — report only

**Route/location:** GET `/join/:token`; `app/storage/invites.mjs:114`, `:140`, `:155`; `app/server.mjs:1185`.

**Attack:** Someone obtains a link from browser history, a copied message, a screenshot or an upstream URL log. Although each browser session expires after 30 days, the original invite has no expiry and can mint another session indefinitely until revoked. Rejoining also evicts the oldest browser once 32 sessions exist, so a leaked link can repeatedly displace legitimate sessions. Successful joins refund the failed-join budget. Administrator invites carry administrator power explicitly.

**Proposed fix:** Offer expiring/one-use enrollment links, explicit rotation and per-link successful-enrollment budgets; keep reusable links only as an explicit choice. Consider a fragment-to-same-origin-POST exchange so secrets do not enter HTTP request paths. Requires sidecar schema migration and deliberate invitation UX. Existing immediate revocation, hash-only persistence, session lifetime and 32-session cap work as implemented. Treat shared member links as credentials, not merely identifiers.

### R8 — Low: missing-file errors exposed deployment paths — fixed

**Routes/location:** authenticated static routes such as GET `/` when the web root is missing, and missing file-backed reads; START `app/server.mjs:2132`; candidate `app/server.mjs:2153`.

**Attack:** Request an allowed but absent static file. The ENOENT response includes the raw realpath/open error, which exposes the absolute checkout/asset root. Authentication limits who can collect it, but a member needs no administration permission.

**Fix/evidence:** ENOENT responses now say only `Not found.`. The regression supplies a missing synthetic web root and asserts the entire 404 JSON body. Existing status-500 replies are generic and omit stacks. Server startup logs omit invite paths; stored feedback/invite labels redact join URLs. No HTTP request logger was found in the application. Proxy/browser logging remains outside this repository review.

### R9 — Low: delayed private reads have inconsistent revocation rechecks — report only

**Routes/location:** GET `/api/backup`, `/api/backups/:id`, `/api/training-plan`, `/api/tasks`, `/api/predict`; `app/server.mjs:1456`, `:1580`, `:1623`, `:1633`.

**Attack:** While a link is valid, start a slow queued backup/calculation read; revoke the invite before its await completes. Several handlers authenticate on entry but do not recheck before sending the result. In contrast, Area check, Sandbox, overlay archive reads and usage reads explicitly recheck. This concerns already-authorized in-flight work; it is not evidence that a new request after revocation authenticates successfully, or that already-sent bytes can be recalled.

**Proposed fix:** Define whether revocation cancels in-flight reads; if required, use an identity-generation/cancellation mechanism and a shared pre-send authorization check on all delayed private responses. Needs coordinated streaming and cached-response behavior. Code-inspection finding; no timing exploit is claimed from the tests here. Accepted mutations are serialized against revocation and reauthenticate after body receipt.

## Authentication, origin, validation and response conclusions

- Invites and browser sessions each use 32 random bytes (256 bits), encoded as 43 base64url characters. Comparisons use timingSafeEqual on equal-length inputs; only SHA-256 hashes enter `invites.json`. Master creation also uses 32 random bytes. Invite IDs are identifiers, not secrets. Records validate types and allowed fields; atomic sidecar writes use mode 0600. There are at most 1,000 invites and 10,000 active sessions. Restoring gameplay does not restore revoked authentication sidecars.
- A master token or master session authenticates only from the private network context and never when the Funnel marker is present. Forwarding is trusted only from loopback or the exact bound private address. A chain/invalid X-Forwarded-For becomes an unknown public client; IPv4-mapped IPv6 is canonicalized. This depends on the deployed proxy overwriting forwarding headers as documented. Untrusted peers cannot assert a private XFF address.
- All normal public POSTs require the configured exact HTTPS origin, matching Host and Origin, and reject Sec-Fetch-Site: cross-site. Private cookie writes require Origin unless the legacy Authorization exemption applies; that private no-Origin exemption currently checks the presence of Authorization, rather than proving that it supplied authentication (`app/security/request.mjs:63`). An arbitrary Authorization header alongside a valid private cookie can select that exemption. No browser-origin bypass was demonstrated: cross-site JSON requests require preflight, supplied foreign/null origins fail, and CORS headers are absent. A follow-up should bind the private exemption to a validated bearer principal. Native plugin POSTs are a deliberate, independently authenticated exception.
- Browser cookies are host-only, HttpOnly, SameSite=Lax, Path=/, Max-Age=30 days, with Secure when the transport context is HTTPS. No Domain attribute or wildcard CORS is emitted. Funnel deployment must provide HTTPS and the correct proxy context; do not expose the plaintext listener directly. GET `/join/:token` intentionally exchanges a credential and sets a cookie without a POST origin check; this permits login/session substitution using a known invite link. A confirmation-based enrollment flow would address that alongside R7.
- Common headers include nosniff, no-referrer, DENY framing, a restrictive CSP, disabled camera/microphone/location and HSTS over secure requests. Gallery preview alone allows same-origin framing for administrators. Data/error responses are private/no-store; static bytes are private/revalidated or private/immutable only for digest-bearing names. `app/http-response.mjs:45` negotiates encoding, computes validators per encoding, supports HEAD/304 and bounds cached retained bytes including compressed variants. No cross-user shared public cache or credentials in ETags were found. Compression still costs CPU for dynamic responses, covered partly by R3 and R6.
- Route decoding rejects dot segments, backslashes and NULs. Static module routes are explicit allowlists. `containedFile` resolves both root and file, then enforces realpath containment; asset providers use `safeArtFile` and catalogue/manifest allowlists. Backup IDs have a strict filename regex plus realpath/archive validation. Dataset-input paths must be exact registered JSON input keys. No arbitrary filesystem path or remote fetch URL is selected by a request. Operator-provided roots/addons are outside the remote-input boundary.
- Queries have no blanket strict schema: many handlers ignore unrecognized/duplicate keys and use the first value. Critical identifiers resolve against known members/chunks/catalogues, history limits are 1–500 and search is at most 200 characters, revision numbers are safe integers, and Area check/overlay/plugin queries reject unsupported forms. Node's HTTP header/request-target budget bounds URL size. No query-based authorization bypass or traversal was found; calculation budgets now also cover HEAD. RuneMetrics uses saved player names and fixed integration endpoints; a caller cannot supply an arbitrary URL.

### Remaining risks and recommendation

The 1 MiB ordinary-body limit can reject unusually large legacy command clients; large backup transfers keep their dedicated streaming path. The 600/minute calculation budget and 16-stream identity cap can affect rapid previews or many browser tabs and may need tuning. Slow SSE clients are disconnected and must reconnect. Limits are per process and reset on restart; they do not replace deployment connection controls or solve R6. Reusable invite lifetime, the shared-gameplay trust model and in-flight read revocation remain explicit design follow-ups. No deployment configuration or private addon was validated. Two independently reproduced baseline test failures remain.

Recommendation for these contained changes: **MERGE-CANDIDATE**.
